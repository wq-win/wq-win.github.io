# 第 25 天｜MADDPG：训练时看全局，执行时各自行动

[系列首页](README.md) · [上一篇](24-icm.md) · [下一篇](26-her.md)

**原论文与版本**：*Multi-Agent Actor-Critic for Mixed Cooperative-Competitive Environments*，2017。[原论文](https://arxiv.org/abs/1706.02275)。

## 一、先用一分钟讲明白

**研究问题**：多个学习者使彼此的环境不断变化

**旧方法卡点**：独立Critic把其他策略变化误认为环境噪声

**作者主张**：为每个智能体用集中Critic，Actor执行时只用局部观测

**论文证据**：合作、竞争和混合粒子任务实验显示作用

**一句话**：在多智能体、集中训练分散执行、连续策略梯度中，作者通过“为每个智能体用集中Critic，Actor执行时只用局部观测”应对“多个学习者使彼此的环境不断变化”这一问题；证据边界或代价是：集中信息和联合动作输入限制可扩展性。

## 二、研究背景与问题定义

本篇将“多个学习者使彼此的环境不断变化”放在多智能体、集中训练分散执行、连续策略梯度的边界内研究。独立Critic把其他策略变化误认为环境噪声。先固定下表中的任务、反馈与信息权限，再判断后面哪一项改动真正回答了这个问题；算法机制有效与适用于任意环境是不同结论。

| 要素 | 本文设定 |
|---|---|
| 研究场景 | 多智能体、集中训练分散执行、连续策略梯度 |
| 状态／观测 | Actor用局部o_i；Critic用联合信息x |
| 动作 | 每个智能体a_i，联合为a_1…a_N |
| 奖励或学习信号 | 可合作共享或各自不同奖励r_i |
| 终止／边界 | 联合任务终止 |

## 三、方法：到底改了什么

每个Actor只负责自己的动作，但Critic可看其他智能体实际做了什么，从而让条件分布更稳定。与单智能体DDPG相比，关键修改是价值函数的条件信息；训练时额外信息必须在评估声明中说清楚。原文还讨论策略集合与对手建模，核心代码先聚焦集中Critic。

### 关键公式与符号

$$\nabla_{\theta_i}J_i=E[\nabla_{\theta_i}\mu_i(o_i)\nabla_{a_i}Q_i(x,a_1,\ldots,a_N)].$$
只有a_i路径对Actor i反传；别的动作应按该更新的采样与停止梯度约定处理。

### 输入 → 处理 → 输出：教学伪代码

以下伪代码展示核心更新流程；简化条件见代码注释与后文。

```text
用各Actor+探索噪声联合交互
存储联合观测、动作、各奖励与后继观测
每个智能体i：
  用所有目标Actor生成后继联合动作
  y_i←r_i+γ*(1-done)*目标Q_i(x_next,联合动作)
  更新集中Q_i
  用μ_i(o_i)替换联合动作中的a_i
  最大化Q_i更新Actor i，冻结其他Actor
  软更新目标网络
部署：每个Actor只接收自己的o_i
```

**实现要点**：集中信息和联合动作输入限制可扩展性。

### 三种“优化”要分开

| 层次 | 这里具体是什么 |
|---|---|
| 数学目标／训练损失 | 每个智能体最大化自身回报；集中Critic提供局部Actor梯度 |
| 机制改变 | 为每个智能体用集中Critic，Actor执行时只用局部观测 |
| 评价改善的指标 | 各智能体回报、合作／竞争任务结果 |

## 六、贡献、代价与局限

**作者贡献**是可处理混合互动的集中评价。**本文分析**：联合输入随人数增长，训练中熟悉的对手分布也可能与部署不同。一个智能体回报增加可能意味着别人损失，不能把所有结果都叫整体协作提高。

## 七、帮助建立理解

### 教学例子

以下是教学推演，不是原论文实验。

两机器人同时推箱子，单个机器人观察到箱子不动，不知道自己推错还是伙伴没推。Critic看到双方动作后能区分这两种情况；部署Actor仍只能依据自己的观测行动。

### 五个前置概念

1. **非平稳性**：其他策略更新改变数据规律。
2. **集中训练**：学习时可使用联合信息。
3. **分散执行**：部署时各自凭可用信息决策。
4. **联合动作**：所有智能体动作的组合。
5. **信用分配**：把共同结果归因到参与者行为。
