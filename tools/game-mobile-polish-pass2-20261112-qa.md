# Game continuity and mobile interaction pass 2 — 2026-11-12

This publishes a focused usability pass across the remaining seven standalone games, plus gameplay follow-ups. Jianghu Slay source improvements are complete but its site release is explicitly deferred. It does not assert commercial mini-game parity or native WeChat/Douyin platform integration.

## Improvements

- Doudizhu and Paodekuai: suspend queued AI turns/automatic passes while backgrounded and resume the same turn.
- Spider: validated automatic whole-game restoration, including up to 80 undo snapshots; unavailable storage no longer prevents play.
- Sudoku: undo entry, erase and hint; exclude background time from the timer.
- Net: validated seed-based continuation, last-100-rotation undo, clockwise/counterclockwise touch control, rules and destructive-action confirmation. Hints are not refunded by undo/reset; undo history is session-only.
- Forest defense: validated preparation-point save with level, completed waves, towers, gold and health. An unfinished wave restarts from its preparation point, as the UI explicitly states.
- Snow camp: coal/meal net-rate and shortage guidance; optional inspect-only map prevents accidental spending or assignments.
- Deferred Jianghu Slay release (not included in this site commit): source-generated help/restart dialog focus isolation, inert background, Escape isolation and focus restoration; safe areas, bounded scrolling and 44px controls. Save format and game rules unchanged.

## Source provenance

The independent source repository is https://github.com/wq-win/JianghuSlay . Its original commit `1649bd4` generated byte-for-byte the existing site release, including app.js and all assets. Changes were made in source and built, not hand-edited in the minified release. Source changes and their tests must be retained in that repository alongside this release.

## Validation and limits

Run `npm run build`, `npm test`, and `git diff --check` in the site repository. Added regression cases are included in existing game UI suites and `tools/net-session-test.cjs` (`test:game-polish`). Independent Jianghu rules tests: 294 passed, one skipped; UI tests: 58 passed, including cancel-restart save preservation.

Local preview is not accessible from the available cloud browser, and the native Chromium app did not open a window. Automated DOM checks do not establish rendered mobile layout. Real phones, embedded WebViews, notches, low-end-device performance, every level and cross-browser storage behavior remain unverified. Post-deployment public browser checks, if performed, are reported separately.

## Follow-up gameplay corrections (2026-11-14)

- Sudoku clue removal now retains exactly one solution, with a bounded 81-cell pass; this addresses multi-solution boards being checked against one stored solution.
- Parking reduces mandatory departures from 3,200 across 16 levels to 460, with measured dependency-chain difficulty rather than car count alone. Existing v3 in-progress boards migrate without changing their geometry or remaining vehicles; see `parking-pacing-qa.md`.
- Meadow match changes new runs from 288 tiles on every level to 36/54/72/96/120 tiles, with increasing variety/layers. Versioned restoration retains old 288-tile boards and their replay histories.
- Water sort confirms before restarting or replacing an active board, including repeated/cancelled actions and animation races.
- Jianghu source changes are merged in https://github.com/wq-win/JianghuSlay/pull/5 (`75b1fe3dd2a89fdf65fe2d83f0e99efc5d5a5d97`). The site release still requires separate publication.

## Feedback and tactics follow-up

Forest defense now has six waves per level, three map families, four enemy groups, upgrade specializations, sell/rebuild and three-star challenges. Its v2 checkpoint does not overwrite the original v1 key; legacy level position migrates with an explicit rebuild notice instead of incorrectly carrying 15-wave economy into six-wave rules. See `tower-tactics-20261113-qa.md`.

The shared feedback component is used by Net and Forest defense: explicit event-driven visual cues, optional short synthesized audio and optional conservative vibration. Sound/vibration default off, unsupported or rejected vibration degrades to visual feedback, background pages stop output, and reduced-motion suppresses movement and vibration. This is a browser-capability fallback, not a promise of iPhone vibration or real-device validation. Existing game sound systems are not double-played.
