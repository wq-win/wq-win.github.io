084｜Mixtral：用更多参数储存能力，用少数专家处理每个 token

返回目录 · 发展时间线

论文：Albert Q. Jiang 等，Mixtral of Experts，2024。本文依据论文首版的架构、评价、指令微调和路由分析全文；官方实现见代码仓库。论文是较短的模型报告，预训练数据总量、完整优化配置等未披露，不能把架构可运行误称为训练可完整重建。

一分钟理解：8×7B 不等于八个完整助手投票

如果每个 token 都使用模型全部参数，增加容量通常也会增加计算。稀疏专家模型把一些子网络复制成多个专家，每次仅激活其中少数，让参数容量与每 token 计算量部分分离。

Mixtral 在每个 Transformer 层的前馈部分放置 8 个专家，由路由器为每个 token 选择 2 个，其输出加权相加。注意力等部分共享，并不是先让八个独立的 7B 聊天模型各写答案，再举行投票。

作者展示较强的数学、代码和多语言能力。证据支持它在所比较的多项基准上，以较少活跃参数达到大型稠密模型的水平；不支持把“约五倍更少活跃参数”直接翻译成“所有设备上五倍更快或五倍更省显存”。

一句话：在大容量语言建模中，通过 token 级稀疏前馈路由，提高容量与活跃计算的比值，代价是总权重存储、路由调度和专家负载不均。

五个前置概念

五个前置概念：MoE用多个参数分支扩展容量；路由器按输入选择分支；活跃参数描述一次前向实际用到的参数；专家并行把不同专家分布到设备；多数投票解码用多次候选提高答案选择效果并增加推理成本。

背景：三个不同的“模型大小”

理解 Mixtral，先分清总参数、活跃参数和运行显存。总参数决定要存多少权重；活跃参数近似描述处理一个 token 时访问哪些计算路径；运行显存还包含 KV cache、激活、通信缓冲和框架开销。

论文给出的数量级是约 47B 总参数、约 13B 活跃参数。不是 8×7=568\times7=568×7=56B，因为没有复制八套完整注意力和嵌入；也不是 2×7=142\times7=142×7=14B 的精确活跃量，因为共享与专家组件的比例不同。

这是无环境交互的语言预训练及后续指令/偏好微调，不是机器人式在线强化学习。路由器选择的是内部计算分支，不能把它直接当作外部动作策略；专家输出是向量，不是完整自然语言答案。

与早期 MoE 论文的关系也很具体：Mixtral 沿用稀疏路由思想，报告其在开放权重、实用语言模型规模上的效果。它不是 MoE 的发明者。其意义在架构、能力和可部署实现的组合。

方法：token 每过一层，都重新选择专家

令当前 token 的隐藏向量为 xxx，路由参数为 WgW_gWg​。先计算 8 个分数，只保留最大的两个，再做 softmax：

g(x)=softmax⁡(Top2⁡(xWg)),y=∑i=18gi(x)Ei(x).g(x)=\operatorname{softmax}(\operatorname{Top2}(xW_g)),\qquad y=\sum_{i=1}^{8}g_i(x)E_i(x).g(x)=softmax(Top2(xWg​)),y=i=1∑8​gi​(x)Ei​(x).

未被选中的 logits 视为负无穷，对应权重为零，所以无需计算这些专家。EiE_iEi​ 是独立参数的 SwiGLU 前馈网络；gig_igi​ 是组合权重。被选专家不是每段对话固定一次，也不是按任务标题永久分配，而是随 token、层和上下文变化。

SwiGLU 专家可抽象为

Ei(x)=Wo,i[SiLU⁡(Wa,ix)⊙(Wb,ix)].E_i(x)=W_{o,i}\left[\operatorname{SiLU}(W_{a,i}x)\odot(W_{b,i}x)\right].Ei​(x)=Wo,i​[SiLU(Wa,i​x)⊙(Wb,i​x)].

这个形式把非线性门控与通道变换结合。不同专家有自己的矩阵，注意力子层仍负责 token 之间的交互；MoE 前馈子层在得到上下文化表示后逐 token 处理。

表 1 的架构为 32 层、隐藏维度 4,096、32 个查询头、8 个 KV 头、头维度 128、专家中间维度 14,336、词表 32,000，支持 32,768 的稠密上下文。GQA 节省 KV，MoE 控制前馈活跃计算，它们的收益来自不同位置。

输入：token 序列和当前层隐藏状态
对每个 Transformer 层：
    用共享注意力处理上下文，获得逐 token 表示
    对每个 token 计算 8 个路由 logits
    选出 Top-2 专家，将两项权重归一化
    按专家分组/分发 token，批量运行对应 SwiGLU
    将专家输出送回原 token 位置并加权相加
    完成残差等常规层操作
语言模型头产生下一 token 分布
训练时：依据语言建模目标反向传播
输出：token 分布；每 token、每层仅激活两个专家

这段伪代码解释计算路径，不补写论文未报告的负载平衡损失、容量系数或 token 丢弃规则。MoE 训练常见某类技巧，不代表 Mixtral 报告明确采用了同一配置。

若专家分布在不同 GPU，输入要发到相应设备再取回，形成专家并行。某一批 token 集中选中少数专家时，设备负载可能失衡；如果各专家收到的 token 太少，矩阵运算也难以充分利用 GPU。稀疏 FLOPs 不自动转化为等比例墙钟收益。

指令版另外执行 SFT 和 DPO。二者改变模型行为，但论文没有给完整数据、超参数和模块消融，因此不能从指令成绩反推 DPO 独自贡献了多少。

证据二｜表 3—4：更完整地限定比较条件。 表 3 的 5-shot GSM8K 为 Mixtral 58.4、GPT-3.5 57.1、Llama 2 70B 53.6；MT-Bench 则为 8.30 对 GPT-3.5 的 8.32。表 4 的德语 MMLU 为 71.5 对 Llama 2 70B 的 64.2，相差 7.3 个百分点。多语言增益与上采样多语言数据同时发生，不能将全部提升归给专家结构。

证据四｜图 7—8、表 5：专家并没有显现简单的学科分工。 路由分布在 arXiv、PubMed、PhilPapers 等领域较接近，作者没有观察到明显的按主题分配。代码缩进和某些词的路由表现更像语法局部模式。表 5 中 arXiv 第 15 层相邻 token 第一专家相同为 27.9%，随机基线 12.5%，支持局部性；但总体频率相似不能证明专家完全没有语义功能，仍需因果干预等更细分析。

贡献、局限与一个参数算例

主要贡献是展示稀疏专家在实用开放语言模型中的能力/活跃参数优势，并给出可供研究的路由观察。论文提供架构和权重入口，但训练配方披露程度有限，属于理解与复现之间的重要边界。

自构算例。 假设一个模型共享部分有 3 个单位参数，每套专家跨层合计 5 个单位，则 8 专家总参数为 3+8×5=433+8\times5=433+8×5=43，Top-2 活跃量为 3+2×5=133+2\times5=133+2×5=13。这说明总量和活跃量如何分离，不是 Mixtral 的精确参数拆分。若全部专家常驻设备，43 个单位仍要存储；不能因为一次只算 13 就只准备 13 的权重内存。

再设两个 token 都选择专家 1、2，另两个选择专家 7、8：系统可以按专家把 token 合批。若一整批都选择专家 1，分布式设备可能一边拥堵一边空闲。有效部署需要看路由分布和硬件，而不只是 Top-k。

自测：能否避免 MoE 的三个常见误读

1. 为什么 8×7B 不是八个完整 7B 模型的集成？

答案：复制的是每层前馈专家，注意力等组件共享；每个 token 在每层由路由器选两个向量变换分支。系统没有生成八份完整答案再投票。因此总参数不是简单56B，活跃参数也不是简单14B。

2. 约13B活跃参数是否意味着与13B稠密模型相同显存和速度？

答案：不能。总专家权重仍约47B，常驻存储、缓存和路由通信都占资源；同一批次可能访问很多不同专家。活跃参数主要描述计算路径，实际速度还取决于批量、专家负载、内核和互联。

3. 为什么表2的GSM8K 74.4不能直接与表3的58.4比较出退步？

答案：二者评价协议不同，表2使用8-shot与maj@8，表3标注5-shot。示范和多候选聚合改变推理预算及答案选择。必须锁定同一设置后比较模型，否则只是把不同测量当作同一能力的变化。
