074｜QLoRA：把大模型放进显存，再用小适配器改变它

返回目录 · 发展时间线

论文：Tim Dettmers、Artidoro Pagnoni、Ari Holtzman、Luke Zettlemoyer，QLoRA: Efficient Finetuning of Quantized LLMs，2023。论文、正文 v1、官方代码。本文核对方法、定量实验和训练超参数附录；没有独立复现65B训练，也没有把代码后续版本的默认值当成论文配置。

一分钟理解：参数很少，基座依然很大

LoRA 只更新少量低秩参数，减少了梯度和优化器状态，但训练时仍要把庞大的基座模型放进显存。QLoRA 再向前走一步：基座以4位格式存储，使用时恢复到较高精度参与计算，只训练额外的 LoRA 分支。

三项技术共同降低显存压力：NF4 为近似正态权重安排非均匀量化值；双重量化压缩量化尺度；分页优化器缓解偶发显存峰值。它不是把所有计算、梯度和参数都改成4位。

作者展示65B模型可以在单张48GB GPU上做适配训练。但“保留全参数微调能力”要按实验拆开：较小模型有全参数对照，7B—65B的主要精度比较是16位 LoRA 对照，并没有全面验证65B全参数微调的等价性。

一句话总结：在大模型适配受显存限制时，通过冻结4位基座、训练高精度低秩分支并压缩辅助状态，大幅降低训练显存门槛，限制是激活、序列长度和传输成本仍然存在，任务质量也依赖适配位置和数据。

五个前置概念

五个概念：量化码本规定低位值对应什么实数；反量化恢复近似高精度值而非原始精确值；低秩更新用两个瘦矩阵表达参数变化；激活检查点用重算换保存内存；分页通过CPU/GPU间迁移状态应对容量压力。

背景：冻结权重仍然需要参与反向传播

全参数微调需要权重、梯度、优化器状态以及前向激活。LoRA 去掉了绝大多数可训练权重状态，但不能跳过整个基座计算，否则前层适配器收不到正确梯度。

QLoRA 属于监督微调与数值表示技术，论文聊天模型 Guanaco 也使用交叉熵，不使用强化学习。即使训练数据名为 HH-RLHF，选择其中响应做监督训练也不等于执行 RLHF。

设输入 X∈Rb×dX\in\mathbb R^{b\times d}X∈Rb×d，基座权重近似为 W^\widehat WW，低秩矩阵为 A∈Rd×rA\in\mathbb R^{d\times r}A∈Rd×r、B∈Rr×oB\in\mathbb R^{r\times o}B∈Rr×o：

Y=XW^+sXAB,W^=Dequant⁡(W4bit,scales).Y=X\widehat W+sXAB,\qquad \widehat W=\operatorname{Dequant}(W_{4bit},\text{scales}).Y=XW+sXAB,W=Dequant(W4bit​,scales).

sss 是适配器缩放系数。训练更新 A,BA,BA,B，不更新存储的 W4bitW_{4bit}W4bit​。但若要给前层传梯度，仍需计算与 W^⊤\widehat W^\topW⊤ 有关的输入梯度。冻结表示“不求基座权重更新”，不表示“把整个基座放进无梯度上下文”。

方法：NF4、双重量化和分页分别解决哪一项？

NF4 解决有限量化值怎样分配。 将权重分块并按绝对最大值归一，使用由正态分布分位数启发的16个表示值。权重密集的零附近分配更细的间距，稀疏尾部间距更大，并保留精确零。它不同于标准 FP4 的指数尾数组合。

作者用信息论最优描述这项设计，需要保留分布前提：实际权重经分块和最大值归一后未必严格服从正态分布，分位数设计也不等于对所有下游任务损失全局最优。经验优势由量化和微调实验支持，而不是一条保证任何模型无损的定理。

双重量化解决尺度本身占空间。 每64个权重保存一个32位尺度，会额外花费 32/64=0.532/64=0.532/64=0.5 bit/参数。将这些尺度再以8位存储，并每256个尺度设置二级32位尺度，额外成本约为：

864+3264×256≈0.127 bit/参数.\frac{8}{64}+\frac{32}{64\times256}\approx0.127\text{ bit/参数}.648​+64×25632​≈0.127 bit/参数.

因此节省约0.373 bit/参数。它压缩的是量化元数据，不是对同一权重连续量化两次以神奇地恢复精度。实际还有偏移等辅助信息，计算是主要平均成本模型。

分页优化器解决峰值。 使用统一内存，在需要时把优化器状态在 GPU 和 CPU 内存之间迁移。这能帮助避免偶发显存不足，却不是免费增加显存；频繁换页可能造成传输等待。它也没有把所有激活自动压到4位。

输入：预训练模型 W、监督样本 D
W4, first_scales = blockwise_NF4_quantize(W, block=64)
scale8, second_scales = quantize_scales(first_scales, block=256)
freeze W4 and quantization metadata
attach trainable LoRA to transformer linear layers
for batch in D:
    on demand, dequantize required weights to BF16
    compute base output plus LoRA output
    loss = cross_entropy(on dataset-specific supervised tokens)
    backpropagate through fixed base operations into LoRA parameters
    update LoRA with paged optimizer
输出：固定量化基座和训练后的适配器

损失还是交叉熵，量化不是新任务目标。LoRA 覆盖位置是一项关键训练设计：原文图2发现只放在 query/value 投影不足，覆盖 Transformer 线性层更接近较强16位基线。不能只比较位宽，却把适配器覆盖范围也悄悄改变。

证据一：表2，位格式比较。 跨模型平均困惑度 Int4为34.34，FP4 E2M1为31.07，FP4 E3M0为29.48，NF4+DQ为27.41。越低越好。它支持所测试权重分布下 NF4 的优势；这是跨配置聚合，不是单个65B模型的困惑度，也不直接证明聊天质量提升同样大。

证据三：表4，大模型的对照是谁。 跨尺寸与数据的16位 LoRA平均MMLU53.0，NF4+DQ53.1；33B/FLAN一项却从60.5到59.2，65B/FLAN从62.5到63.9。平均相近包含正负变化，不能推出每种任务都相同。更不能把大尺寸 LoRA 对照写成完整全参数微调对照。

证据四：表5和表6，数据适配具有任务性。 65B FLAN 的MMLU63.9高于Guanaco62.2，但 Vicuna 相对评分48.4低于Guanaco99.3。不同数据塑造不同能力，不能用单个考试成绩替代聊天评价，也不能把“小数据更好”推广成数据规模不重要。

证据五：表6、表7与§5.3，评委有偏差。 Guanaco65B 相对ChatGPT评分99.3%，95%区间为±4.4个百分点；交换回答顺序时96.7%与101.9%不同。人类与GPT-4系统排序 Spearman相关0.55，逐例一致性Fleiss κ为0.25。99.3%只是一个小基准、特定评委和归一方式下的评分，不是99.3%的通用能力，更不是几乎同样可靠的保证。

分页的效果还应另看§4：作者没有给出全面的峰值分页消融，报告的某个65B配置速度与普通优化器相近。可以说它解决了可运行性问题，不能声称任何长序列负载都没有额外开销。

贡献与局限：省出的资源应该怎样使用？

QLoRA 的贡献是让低位存储与可训练高精度适配器形成可用配方，拓宽单卡可实验的模型规模。量化误差可以通过适配器在任务分布上部分补偿，但低秩更新没有义务修复所有输入上的数值差异。

作者同时强调聊天基准不够可靠，并给出失败案例。进一步分析还包括：适配器部署必须匹配量化基座；合并到权重再重新量化可能改变输出；高质量数据与任务匹配并不是同一个概念；节省参数状态后，长序列激活可能成为新瓶颈。省显存意味着更可行，不自动意味着更快或更准确。

自测与答案

1. 基座被冻结，为什么不能把整个基座前向都放在 no_grad 中？

答案：前层适配器的梯度需要穿过后续基座运算传播。可以不保存基座权重梯度，但必须保留对输入激活的求导路径。否则会切断某些可训练分支，而不是正确实现QLoRA。

2. NF4加双重量化后，每个参数是否恰好只占4位？

答案：不是。4位是权重编码，还要尺度等元数据；论文主要平均模型为4+0.127 bit，实际还存在未量化部分、适配器和运行时状态。双重量化减少的是尺度开销，不会使所有训练状态都变成4位。

3. 怎样设计实验检验“QLoRA和全参数微调一样好”？

答案：选择同一基座和数据，固定训练与调参预算，同时比较全参数、16位LoRA和QLoRA，保持适配器覆盖一致，报告多种任务、随机种子、峰值显存和耗时。这样才能分别定位低秩约束、量化误差与数据变化的影响，而不是只看一个平均分接近。
