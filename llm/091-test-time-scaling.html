091｜Test-Time Scaling：不是一律多想，而是决定把计算花在哪里

返回目录 · 发展时间线

论文：Charlie Snell、Jaehoon Lee、Kelvin Xu、Aviral Kumar，Scaling LLM Test-Time Compute Optimally can be More Effective than Scaling Model Parameters，2024。依据原文 v1的搜索、修订、成本比较与附录。主要模型为 PaLM 2-S*，并非公开权重的完整可复现实验；下文不把图上的估计值写成未经报告的精确成绩。

一分钟理解：同样生成 64 次，可以有很多花法

面对一道题，可以独立生成 64 个答案，也可以沿一个答案反复修订 64 次，还可以开 8 条路线、每条修订 8 次。即使生成数量相同，这些策略探索的答案分布也不同。

论文研究两根调节杆：用验证器引导搜索，或训练模型根据先前尝试修订回答。作者发现哪种方法划算取决于题目对当前模型有多难。简单题适合局部改进，中等难题可能需要多路线搜索；最难题则未必能靠增加尝试解决。

按难度选择策略，在部分曲线中能以约四分之一的所计生成预算达到更好的结果。但难度估计本身很昂贵，原文没有把这部分计入主要比较。这是一项预算分配的潜力研究，还不是完整部署方案的成本保证。

一句话：在模型已有部分解题能力的数学任务中，通过按难度分配搜索与修订预算，提高推理计算的利用率，代价是验证器训练、难度识别开销以及最难题上的能力上限。

五个前置概念

五个前置概念：proposal distribution决定候选从哪里来；PRM评估中间推理前缀；beam search按分数保留有限前缀；交叉验证把配置选择与效果测量分开；生命周期 FLOPs同时考虑一次训练和累计推理需求。

背景：推理预算扩大有两个前提

首先，生成器必须有机会提出有用路径。若它对题目需要的核心方法完全不会，反复采样可能只得到更多错误。其次，系统要能把较好的候选留下；如果评分器容易被骗，更强搜索反而更快找到它的漏洞。

这里要分清 proposer 与 verifier。前者生成候选，后者评价候选；修订模型通过把历史答案放进输入来改变生成分布，搜索算法通过筛选和扩展来改变最终输出分布。测试时没有为每个问题重新训练所有权重，但前期专门训练了修订和验证能力。

题目难度也是相对模型定义的。人类标成难题，不代表某模型不会；人类觉得简单，也可能是模型的盲点。作者因此用该模型的成功概率分组，而不单靠 MATH 的人工难度等级。

方法一：验证器引导的搜索

PRM 预测的是后续成功，不只是本步逻辑对错

作者从解答中间前缀继续做 Monte Carlo rollout，以最终正确比例训练过程奖励模型。因而某一步的分数近似：

Vπ(h)=Pr⁡o∼π(⋅∣h)(最终答案正确).V_\pi(h)=\Pr_{o\sim\pi(\cdot\mid h)}(\text{最终答案正确}).Vπ​(h)=o∼π(⋅∣h)Pr​(最终答案正确).

hhh 是当前推理前缀，π\piπ 是生成器。它取决于生成器后续能力，不完全等于“这一步数学推理本身正确”的标签。使用其他模型产生的过程标签可能引入分布偏移。

基线 best-of-N weighted 生成多条完整解答，以最终步骤的 PRM 分数给整条解答评分，再把相同最终答案的分数相加：

a^=arg⁡max⁡a∑i:ans⁡(oi)=aV(oi).\hat a=\arg\max_a\sum_{i:\operatorname{ans}(o_i)=a}V(o_i).a^=argamax​i:ans(oi​)=a∑​V(oi​).

这不同于单纯挑最高分的一条，也不同于一票一权的多数投票。最后一步评分优于最小值和分数乘积，是此处软 rollout 标签下的实验结论，不能复制成所有 PRM 的固定规则。

搜索选择继续哪些前缀

Beam search 在每层生成候选，保留高分前缀，再从保留项扩展。论文用 NNN 表示该轮候选预算、MMM 表示每个保留项的扩展数，保留 N/MN/MN/M 项；不要套用其他代码库的 beam-width 命名后改变原算法。

Lookahead 在评分前再向前模拟若干步，用更晚的价值估计评价当前前缀。它可能看得更远，也消耗更多生成；本文不能作为所有 MCTS 变体的穷尽比较。

方法二：让模型学会根据历史尝试修订

作者并非只加一句“请检查”。先每题采样 64 个答案，将正确答案与若干错误答案组成训练序列，优先使最后一个错误答案在字符编辑距离上接近正确答案。模型学习在错误历史条件下生成正确回答。

训练最多放入四个错误尝试；测试时可运行更长链，但仅保留最近四次回答。多条链还可以并行运行，最后用验证器或多数投票选答案。

这里存在分布变化：训练历史都是错误答案，测试历史可能已经正确。论文观察到朴素修订会把约 38% 的正确答案改错，因此“最后一版最好”不是可靠选择规则。候选保存和答案选择是完整方法的一部分。

方法三：按难度选择策略，而非求出万能最优

令 η\etaη 表示搜索宽度、前瞻长度或顺序与并行比例，预算为 BBB。理想目标是：

η∗(q,B)=arg⁡max⁡ηPr⁡(输出正确∣q,B,η).\eta^*(q,B)=\arg\max_\eta \Pr(\text{输出正确}\mid q,B,\eta).η∗(q,B)=argηmax​Pr(输出正确∣q,B,η).

部署不知道真实答案，不能直接计算这个最优值。论文用五个难度分组近似，对每个组选择较好的配置。Oracle 难度来自 2048 次采样的真实正确率；predicted 难度来自同样规模采样的验证器平均分。

两者都要花计算，后者只是去掉真实答案依赖，没有去掉费用。原文 §3.2 与附录 C 明确未计这部分成本，并用分组内两折交叉验证减少“同一数据既挑配置又测配置”的偏差。这不等于已证明难度是严格统计意义上的充分统计量。

离线：训练生成器所需的修订能力与验证器
研究阶段：估计每题难度，分为五组
对每组和预算，在一折数据上选择搜索或修订配置
在另一折测效果，再交换两折

部署式流程（需额外实现廉价难度判断）：
    输入问题与完整计算预算
    估计难度，并扣除该步骤的成本
    选择独立采样、搜索、修订或混合比例
    保留所有候选及验证分数
    按预定规则选答案，而非默认最后一条
    记录生成、验证、难度判断和延迟

后半段是面向实现的建议，不是论文已经验证的廉价端到端算法。研究目标、近似机制和未来可部署版本需要明确分层。

证据：更多计算何时有效，何时被浪费

证据一：图 3，最强搜索不一定最划算。 小预算时 beam search 优于 best-of-N，预算增大后优势缩小甚至反转；lookahead 在匹配生成预算下通常更差。简单组容易过度优化评分器，中等难度组更受益，最难组各方法进展有限。这支持因题选择算法，而非一律加深搜索。

证据二：图 4，难度分配可以提高局部预算效率。 在部分比较点，约 16 次生成的自适应策略接近或超过 64 次 best-of-N 的水平。准确表述是给定所用难度估计与预算口径下的曲线结果；若再加 2048 次难度采样，就不是完整流程节省四倍。

证据三：图 6–8，顺序与并行互补。 单条修订链的逐步成功率能提高，但过度坚持一条路线不总是最好。高预算和较难题存在更合适的混合比例；图 8 给出 64 对 256 次生成的效率例子。验证器或投票选择不可省略，因为修订也会破坏正确答案。

证据四：图 9，大模型与多次推理的交换依赖工作负载。 论文分别分析推理与预训练 token 比例 R=0.16,0.79,22R=0.16,0.79,22R=0.16,0.79,22。简单题或较少推理需求下，小模型加推理更有吸引力；很难的题或很大的推理负载下，增加模型规模更有利。标题中的“can”是条件判断，不是取代预训练的普遍定律。

当推理请求很少，省下的预训练可摊到每题的大量搜索；当请求极多，这种每题额外预算就缩小。公式未完整覆盖注意力长度效应、服务系统效率、串行延迟和难度估计；它是比较尺度，不是发票。

本文真正的新意是系统分析预算分配和问题难度，而非首次提出采样、beam search 或修订。其主要限制是特定模型、数学数据和不完整端到端成本。过程评分过度优化可生成重复低信息步骤，或极短但高分答案，说明奖励投机也会发生在冻结模型的推理搜索中。

一个自构例子与五个前置概念

假设 16 次尝试预算。一道题模型总能列出正确方程，只在末尾加减出错，4 条路线各修订 4 次可能比 16 条从头解答更经济。另一道题必须想到特殊几何构造，反复修改同一错误方程可能没有帮助，独立探索更有价值。

但系统不知道属于哪种题。若为了判断先生成 200 次，就已经超出预算。这个例子显示调度器本身也是算法，必须计算自己的代价。

自测：能否把论文标题讲完整

1. 为什么 predicted difficulty 不需要正确答案，却仍然不能算免费部署？

它通过验证器给大量采样评分估计难度，避免使用真实标签，但论文仍用每题 2048 个样本。生成和评分都要付费，而主要效率曲线未计这部分。真实部署需要廉价预测、在线复用探索结果，或把完整开销加入预算重新比较。

2. 为什么更深搜索可能降低真实准确率？

验证器只是近似评分函数，搜索越强越可能找到高分但错误的输出。简单题已有较好候选时，继续追分可能偏向重复步骤或其他伪特征。增加预算的价值受生成器覆盖与验证器可靠性共同限制，不具有必然单调性。

3. 小模型加推理超过 14 倍大模型，是否说明可以停止扩大预训练？

不能。结果依赖题目难度、累计推理负载、固定预训练数据量和所计 FLOPs。最难题上小模型往往没有足够候选能力，大推理负载也削弱逐题搜索的成本优势。论文说明两类计算可以部分交换，并指出交换不是一比一和无条件成立。
