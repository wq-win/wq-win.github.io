076｜AWQ：量化权重时，为什么要先看激活？

返回目录 · 发展时间线

论文：Ji Lin 等，AWQ: Activation-aware Weight Quantization for LLM Compression and Acceleration，2023。论文、正文 v2、官方代码。本文核对 v2 的方法、定量实验、系统测量和限制附录；没有独立运行量化与速度测试。后续实现变化不包含在本文实证结论中。

一分钟理解：同样的权重误差，后果不一样

线性层计算 y=Wxy=Wxy=Wx。某个权重少了一点点，如果对应输入激活很大，这一点点误差就会被放大。因此，量化时不能只看权重自身的大小，还应看它通常处理怎样的输入。

AWQ 的观察是：按激活大小找到少数重要通道，优先保护它们，可以显著减轻低位量化损失。但直接把这些权重保留为16位会增加混合精度实现难度。最终方法选择先缩放权重通道、反向缩放输入，再统一量化，使重要通道得到更细的有效精度。

表2中 OPT-6.7B 的 INT3-g128 设置，简单量化困惑度23.54，对重要通道取缩放2后降到11.92；继续放大到4却变差为12.36。这个反例说明保护重要通道需要考虑其他通道的损失。

一句话总结：在低位权重量化的部署场景下，通过激活引导的通道缩放和裁剪，改善量化后质量，并结合高效内核实现加速，限制是依赖校准分布、分组方式与具体硬件工作负载。

五个前置概念

五个概念：训练后量化在已有权重上做压缩；校准集提供典型激活统计；通道缩放重新分配数值动态范围；分组量化让小块权重共享尺度；内核融合减少中间存储和启动开销。

背景：权重量化与激活量化不是一回事

本文主要研究 W4A16 或 W3A16，即权重低位、激活维持较高精度。Activation-aware 指算法利用激活信息，不表示激活也被量化到4位。它属于训练后量化，不通过任务损失反向传播微调语言模型，也不涉及奖励或环境交互。

RTN 将每个权重映射到邻近量化值，简单但没有充分考虑输出误差。GPTQ 利用校准输入和近似二阶信息补偿权重舍入误差。AWQ 选择更受限制的搜索空间：根据输入通道的平均激活幅度设置缩放，再搜索一个指数参数，而不是回归调整全部权重。

作者认为这种限制降低了过拟合校准数据的风险。实验提供了跨两个文本领域的支持，但“完全不会过拟合”比实验能证明的范围更强；网格搜索仍然利用了校准样本上的输出误差。

方法：先作等价变换，再接受量化近似

令 S=diag⁡(s1,…,sd)S=\operatorname{diag}(s_1,\ldots,s_d)S=diag(s1​,…,sd​)，在全精度数学下：

WX=(WS)(S−1X).WX=(WS)(S^{-1}X).WX=(WS)(S−1X).

量化后的输出为：

Y^=Q(WS)S−1X,E(S)=∥Q(WS)S−1X−WX∥F2.\widehat Y=Q(WS)S^{-1}X,\qquad E(S)=\|Q(WS)S^{-1}X-WX\|_F^2.Y=Q(WS)S−1X,E(S)=∥Q(WS)S−1X−WX∥F2​.

第一条等式是精确代数关系；第二条引入 QQQ 后一般不再等价。目标是选择缩放使输出误差较小，而不是声称缩放消除了所有舍入误差。输入逆缩放通常可以融合进前一层，减少运行时开销。

设通道激活统计为 aj=E∣Xj∣a_j=\mathbb E|X_j|aj​=E∣Xj​∣，论文把缩放限制为 sj=ajαs_j=a_j^\alphasj​=ajα​，在 α∈[0,1]\alpha\in[0,1]α∈[0,1] 上用20个网格候选搜索。接近0时缩放弱，接近1时更偏重高激活通道；随后也搜索权重裁剪以减少量化步长。

为什么放大会保护通道？若分组的量化步长 Δ\DeltaΔ 近似不变，把权重放大 sss 倍再把输入除以 sss，有效输出舍入误差也约除以 sss。但若放大后的权重抬高了组最大值，新的 Δ′\Delta'Δ′ 也会增长，其他通道反而更粗糙。原文的近似依赖这个平衡，不是任意缩放的误差单调下降证明。

输入：浮点模型、少量校准文本、目标位宽、group_size=128
run calibration forward passes and cache layer inputs
for each supported linear layer:
    activation_scale = mean_absolute_input_per_channel
    for α in grid_of_20_candidates:
        S = diagonal(activation_scale ** α)
        candidate = group_quantize(W @ S)
        error = output_error(candidate @ inverse(S) @ X, W @ X)
    choose the best scaling candidate
    search clipping parameters on calibration outputs
    fuse inverse scaling into compatible preceding operation
    pack all target weights into low-bit storage
输出：低位模型、量化元数据与可执行推理布局

这是算法主线的教学表达。数值实现需要处理零激活、张量布局和尺度融合等细节；不能把伪代码当作与所有网络结构直接兼容的部署库。

三个容易混淆的“优化”

数学上最小化的是校准输入上的局部输出误差；机制上改变的是通道缩放、裁剪与整数表示；实验中改善的是困惑度、任务分数和推理速度。局部误差更小并不自动证明长文本推理更可靠。

“保留1%高精度权重”是验证重要通道存在的分析实验，不是最终 AWQ 必须采用的混合精度格式。正式缩放方案的意义正是尽量保留统一低位格式，让硬件更容易执行。

贡献与局限：高质量压缩需要与运行时一起设计

AWQ 的贡献是将“某些通道更重要”的分析转化为统一低位格式下的缩放方案，并展示校准需求与跨模态表现。系统实现则把存储节省变成速度收益，这与算法精度贡献互相配合，但不是同一个实验问题。

作者承认评测主要集中于困惑度和任务准确性，还需要可靠性、偏差、校准等更广指标。附录C讨论无分组量化时的不足，说明当前机制依赖分组提供局部动态范围，不能随意去掉分组却期待保留同样收益。

进一步分析还包括：激活分布可能因提示格式、语言、长上下文和领域改变；量化不负责修正原模型事实错误；固定分组带来尺度与零点元数据；CPU或不支持所需低位内核的设备未必加速。“模型文件更小”与“每次请求更快”需要两份测量。

自测与答案

1. AWQ 名称里有 activation，是否说明它把激活也变成4位？

答案：不是。它主要做低位权重量化，利用激活统计决定如何保护权重通道。了解输入对权重误差的放大作用，不需要把输入本身也低位化。

2. 为什么缩放和逆缩放在量化前等价，量化后却能改变结果？

答案：实数乘法中两个缩放严格抵消；量化会把不同范围的权重舍入到不同网格点，不能和缩放交换顺序。正是这种非等价性给了重新分配误差的机会，也引入了损害其他通道的风险。

3. 怎样验证一套AWQ实现的3倍加速真的是你需要的收益？

答案：固定硬件、模型、生成长度、batch和提示长度，分别测预填充、逐token解码和端到端时间，同时报告质量和峰值内存。还应比较相同优化程度的FP16运行时，区分量化节省与融合优化；只复制论文短提示结果不足以预测自己的服务。
