### 先接住前作的问题

[Transformer](015-transformer.md)每个头通常保存独立K/V，长历史解码时反复读取的缓存随头数增长。本篇在完全独立与MQA式单组共享之间引入分组；它可与[FlashAttention](059-flashattention.md)的内核、[vLLM](079-vllm.md)的布局组合，改变的是结构轴。

## 一、问题设定：查询头保留多样性时，怎样减少历史KV搬运

缓存避免重复计算历史表示，却不免除下一步读取。若所有查询共享一份K/V，存储更省但表达约束更强；GQA保留多个查询头，调节它们共享多少组K/V，并研究已有MHA检查点怎样低成本适配。

## 二、定义分组共享并分析均值初始化的非等价性

设查询头数为 $H$，KV 头数为 $G$。MHA 对应 $G=H$；MQA 对应 $G=1$；GQA 在两者之间选择。每个查询头仍然有自己的 query 投影，所以共享 KV 不意味着组内所有头产生相同的注意力分布。

对于查询头 $h$，令 $g(h)$ 为所属组，其输出为：

$$
O_h=\operatorname{softmax}\left(\frac{Q_hK_{g(h)}^\top}{\sqrt{d_k}}+M\right)V_{g(h)}.
$$

$d_k$ 是头维度，$M$ 是掩码；自回归自注意力使用因果限制。不同 $Q_h$ 可以针对同一组历史键提出不同查询，因此仍有多种“读取视角”，只是历史信息的写入表示被共享了。

本文不是删掉历史 token，也不缩短上下文窗口。缓存仍然覆盖相同序列，只是每个位置存储的 KV 头更少。它也不同于 FlashAttention：后者主要改变注意力计算与数据搬运组织，GQA 改变参数共享和表示容量。

需要注意原文只对 decoder 自注意力和交叉注意力应用 MQA/GQA，encoder 自注意力保持 MHA。编码器并行处理输入，其性能瓶颈与逐 token 解码不完全相同。

从已有 MHA 检查点转换时，每组的 key/value 投影取组内平均：

$$
W_K^{(g)}=\frac{1}{|I_g|}\sum_{h\in I_g}W_K^{(h)},\qquad
W_V^{(g)}=\frac{1}{|I_g|}\sum_{h\in I_g}W_V^{(h)}.
$$

$I_g$ 是该组的原始头集合。query 和输出投影按转换方案保留。平均值利用全部原始头的信息，是一个初始化选择；因为 softmax 非线性，平均投影后的注意力不等于原先多个注意力输出的平均，所以不能声称这是无损压缩。

随后按原始预训练配方继续训练 $\alpha$ 比例的步数。主实验取 $\alpha=0.05$，即原预训练步数的5%。没有新的专用 GQA 损失；沿用 T5 的预训练目标，让各层共同适应共享结构。

对于仅考虑 decoder 自注意力的简化计算，设层数 $L$、批量 $B$、历史长度 $S$、每个缓存元素 $q$ 字节，KV 存储量近似为：

$$
\operatorname{Bytes}_{KV}=2LBSGd_kq.
$$

前面的2分别对应 key 和 value。在其他条件相同时，GQA 相对 MHA 的缓存比为 $G/H$。这是缓存项的关系，不是总显存或总时间的关系；权重、激活、临时工作区和交叉注意力缓存都可能占用资源。

此外，查询头数量没有减少，很多注意力乘法仍然存在。速度改善主要来自内存流量和更合适的并行布局。原文还讨论了 MQA 的单个 KV 头在多分片上复制的浪费；组数适当增加时，逻辑缓存增加不一定按同样比例转化为物理通信和存储增加。

### 为什么平均 K/V 后还需要继续训练？

即使查询 $q$ 相同，平均键之后的注意力也不等于原来注意力的平均，因为 softmax 是非线性的。设两个头对两个位置的打分分别为 $(4,0)$ 和 $(0,0)$，它们给第一位置的权重为约 $0.982$ 和 $0.5$；先分别归一化再平均得到 $0.741$。先平均键导致打分变为 $(2,0)$，归一化后却为 $0.881$。即使值向量暂时保持相同，输出也已经改变。

这解释了两阶段适配各自的作用：均值池化给共享 K/V 一个利用原检查点信息的初始化，继续预训练则让查询、共享表示和其他权重适应新约束。原文§3.3也指出，GQA转换后已经具有合理表现，继续预训练进一步改善质量；不能把适配带来的收益提升为“不训练就完全不可用”。它不是把原模型无损重排，也不能仅凭头数减少比例预测模型质量。

**自构显存核算，未运行。** 对仅计算 KV 缓存的单请求，取 32 层、序列长度 4096、每头维度 128、每数 2 字节。32 个 KV 头需要 $2\times32\times4096\times32\times128\times2$ 字节，即 2 GiB；改为 8 个 KV 组后是 512 MiB。第一个因子 2 表示 K 和 V。查询头数保持 32，并不产生这份历史缓存；权重、工作区、分块浪费和批处理都没有包含在该数值中，因此它是缓存容量下降四倍，不是整个系统显存或延迟下降四倍。

### 共享键值仍允许两颗查询头读出不同内容

设共享的两个key为(1,0)与(0,1)，两颗query分别为(1,0)和(0,1)，忽略相同缩放时分数分别为(1,0)和(0,1)。softmax权重彼此交换，因此读取同一份V也会得到不同输出。GQA减少的是历史K/V副本，不是把组内query的计算与表达全部合并。

教法联系：[Lilian Weng的Large Transformer Model Inference Optimization](https://lilianweng.github.io/posts/2023-01-10-inference-optimization/)。算例为本文自构。

## 三、转换检查点并继续训练以适应共享约束

```text
输入：已训练 MHA 检查点、组数 G、继续训练比例 α
for decoder attention layer:
    divide H query heads into G groups
    for each group:
        shared_K = mean(original_K_projections_in_group)
        shared_V = mean(original_V_projections_in_group)
    retain query projections and compatible output projection
continue pretraining with original objective and data recipe
finetune on each downstream task
decode with G KV heads and H query heads
输出：经适配的 GQA 模型及其质量/时间测量
```

数学目标是原任务损失；机制是共享投影与继续训练；指标是下游分数、稳定性和推理时间。“用5%算力”指利用已有模型后的增量适配，不是从随机初始化得到同等模型只需原训练成本的5%。

## 四、同时读取组数、质量恢复和计时单位

先统一表1和图3的计时口径，再比较组数；继续训练比例与任务质量共同限定“接近MHA”的含义。

| 项目 | 原文设置 |
|---|---|
| 模型 | T5.1.1 Large 与 XXL；主要转换对象为已有 XXL 检查点 |
| 增量训练 | 原预训练数据与配方；5%比例约600 TPUv3 chip-days，不是600天墙钟时间 |
| 下游任务 | CNN/Daily Mail、arXiv、PubMed、MediaSum、Multi-News摘要，WMT14英德翻译，TriviaQA |
| 任务微调 | 学习率0.001、batch128、dropout0.1；训练到收敛，用开发集最好检查点；不是所有任务固定相同更新次数 |

## 五、缓存四倍压缩不保证整体四倍加速

五个概念：**KV cache**存储历史键值避免重复计算；**query头**决定每次如何读取历史；**带宽瓶颈**表示时间主要花在搬数据；**继续预训练**让已有模型适应结构或数据变化；**吞吐与延迟**分别衡量单位时间总工作量与单次请求等待时间。

它让部署约束能够进入模型架构设计，而不必在完全独立的 KV 与完全共享的 KV 之间二选一。

作者承认主实验仅覆盖编码器—解码器结构，没有与从头训练的 XXL GQA 做等预算比较，也承认 ROUGE 不能全面评价生成质量。因此论文没有回答“同样总训练预算下，先训练MHA再转换，是否优于直接训练GQA”。

进一步分析还包括：KV压缩对长序列大批量可能更有价值，但当权重搬运或计算成为主瓶颈时，收益会减弱；转换需要原预训练数据或足够匹配的替代数据；缓存省下来的显存可能用于更大批量，改变延迟与吞吐的折中。质量、总显存和速度应该分别测量。

## 六、把缓存共享结构与内核、分页组合

共享K/V之后，[vLLM](079-vllm.md)继续减少请求间分配浪费，[FlashAttention](059-flashattention.md)优化读写路径。这是结构、布局与内核三个可组合层次，需在共同负载下重新测整体收益。

## 自测与答案

**1. 同组查询头共享 K 和 V，为什么输出仍然可以不同？**

答案：每个头的 Q 仍不同，因而与相同 K 计算出的分数和 softmax 权重不同，可以从同一组 V 中读出不同组合。共享的是历史表示，不是查询方式，也不是最终注意力权重。

**2. 把32个 KV 头改为8个，是否等于模型快4倍、总显存少75%？**

答案：只在相同条件下，自注意力 KV 缓存项缩小到四分之一。模型权重和其他工作区并未同比缩小，查询相关运算也仍存在。必须测量具体瓶颈，才能预测端到端收益。

**3. 为什么不能直接平均头后发布，并宣称和原模型等价？**

答案：注意力包含非线性，平均投影不能保持原输出。需要测量转换后的质量并决定所需适配训练；原文[图5](#llm-v6-073-figure-5)也展示继续训练的作用。即便均值初始化优于其他方案，也只是好的起点，不是等价性证明。
